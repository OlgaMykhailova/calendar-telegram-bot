# Calendar → Telegram

Telegram-бот, який читає події з одного календаря Google і за 5 хвилин до початку надсилає нагадування в Telegram.

Працює як [Cloudflare Worker](https://developers.cloudflare.com/workers/) з розкладом (Cron Trigger) на безкоштовному плані: сервер і увімкнений комп'ютер не потрібні.

## Як це працює

1. Щохвилини Worker отримує токен Google (сервісний акаунт, JWT) і запитує події календаря, що починаються найближчими 5 хвилин.
2. Для кожної події, яка почнеться за ≤ 5 хв (події на весь день і скасовані ігноруються), перевіряє в KV, чи вже надсилав нагадування.
3. Якщо ні, ставить позначку в KV і надсилає повідомлення в Telegram. Якщо надсилання не вдалося, позначка знімається й наступна хвилина спробує ще раз.

Ключ позначки містить час початку, тому **перенесена подія нагадає знову**. Позначки самі видаляються з KV через 6 годин.

Приклад повідомлення:

```
⏰ Через 5 хв
Планерка
🕐 14:30–15:00
📍 Кабінет 5
📹 Google Meet
🔗 Відкрити в календарі
```

## Налаштування

### 1. Telegram-бот

1. У [@BotFather](https://t.me/BotFather) виконайте `/newbot`, отримайте **токен**.
2. Відкрийте свого бота й натисніть **Start** (для групи додайте бота в групу й напишіть там `/start@username_бота`).
3. Для **каналу** додайте бота в адміністратори каналу з правом «Публікація повідомлень». `chat_id` каналу від'ємний і починається з `-100`.

### 2. Google Calendar

1. У [Google Cloud Console](https://console.cloud.google.com/) створіть проєкт і увімкніть **Google Calendar API**.
2. «IAM & Admin» → «Service Accounts» → створіть сервісний акаунт (ролі не потрібні) → «Keys» → «Add key» → **JSON**. Збережіть файл поза репозиторієм.
3. У Google Calendar відкрийте налаштування потрібного календаря → «Доступ окремих користувачів» → додайте email сервісного акаунта з правом **«Перегляд усіх подробиць події»**.
4. У тих самих налаштуваннях, в розділі «Інтеграція календаря», скопіюйте **ID календаря**.

### 3. Cloudflare

Потрібен безкоштовний акаунт на [dash.cloudflare.com](https://dash.cloudflare.com/sign-up).

```bash
npm install
npx wrangler login                      # відкриє браузер
npx wrangler kv namespace create STATE  # виведе id
```

Підставте виведений `id` у [wrangler.toml](wrangler.toml) замість `REPLACE_WITH_KV_NAMESPACE_ID`.

### 4. chat_id

```bash
cp .dev.vars.example .dev.vars   # впишіть TELEGRAM_BOT_TOKEN
npm run get-chat-id
```

Скрипт покаже чати, які писали боту (для груп id від'ємний). Запишіть потрібний.

### 5. Секрети

Значення вводите самі, вони зберігаються лише в Cloudflare:

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
npx wrangler secret put GOOGLE_CALENDAR_ID
npx wrangler secret put GOOGLE_SERVICE_ACCOUNT_KEY < /шлях/до/ключа.json
```

Якщо Worker ще не існує, wrangler запропонує створити його: підтвердіть.

Команди `wrangler` виконуйте в звичайному терміналі в папці проєкту. Неінтерактивні оболонки (наприклад, `!` у чаті Claude) не бачать збереженого входу, див. «Типові проблеми при налаштуванні».

**Те саме можна зробити в дашборді Cloudflare:** Worker → **Settings → Variables and Secrets → Add**, у полі **Type** вибрати **Secret** (не «Text»!) і натиснути **Deploy**. Worker з'являється в дашборді лише після першого `npm run deploy`. Ключ Google вставляйте як повний вміст JSON-файлу, без лапок.

### 6. Деплой

```bash
npm run deploy
```

Якщо після деплою пише, що розклад зареєструвати не вдалось (`workers.dev subdomain`), див. «Типові проблеми при налаштуванні» нижче.

## Перевірка

1. Створіть у календарі подію, що починається приблизно за 6 хвилин.
2. Приблизно за 5 хвилин до початку події в Telegram має прийти повідомлення (з точністю до хвилини). Повторно воно не надсилається: цьому заважає позначка в KV.
3. Логи в реальному часі: `npm run logs`. Помилки запусків видно також на дашборді Cloudflare (Workers → calendar-telegram-bot → Observability).

## Налаштування Worker'а

Змінні в [wrangler.toml](wrangler.toml), розділ `[vars]`:

| Змінна | За замовчуванням | Значення |
|---|---|---|
| `REMINDER_MINUTES` | `5` | за скільки хвилин нагадувати |
| `TIMEZONE` | `Europe/Kyiv` | часовий пояс, у якому показується час |

Секрети: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `GOOGLE_CALENDAR_ID`, `GOOGLE_SERVICE_ACCOUNT_KEY`.

## Локальна розробка

```bash
cp .dev.vars.example .dev.vars   # заповніть усі чотири значення
npm run dev                      # запускає Worker локально
curl "http://localhost:8787/__scheduled"   # вручну запускає «cron»
npm test                         # тести без мережі
```

Локально використовується реальний календар і справжній Telegram, тому повідомлення прийде по-справжньому.

У `.dev.vars` ключ Google має бути **одним рядком в одинарних лапках**: `GOOGLE_SERVICE_ACCOUNT_KEY='{"type":"service_account", … }'`. У подвійних лапках `\n` у приватному ключі перетворюється на справжні переноси, і JSON перестає читатися. Не виводьте вміст `.dev.vars` у термінал чи чат: там токен і приватний ключ.

## Якщо щось не працює

| Симптом (у `npm run logs`) | Причина |
|---|---|
| `Google Calendar request failed: 404` | Неправильний `GOOGLE_CALENDAR_ID` або календар не відкрито для email сервісного акаунта |
| `Google token request failed: 400` | Пошкоджений ключ у `GOOGLE_SERVICE_ACCOUNT_KEY` або сервісний акаунт видалено |
| `Telegram sendMessage failed: 400 … chat not found` | Невірний `TELEGRAM_CHAT_ID` або ви не натиснули Start у боті |
| `Telegram sendMessage failed: 401` | Невірний `TELEGRAM_BOT_TOKEN` |
| `Missing configuration: …` | Не задано один із секретів або KV-привʼязку `STATE` |
| Нагадування не приходять | Подія на весь день (їх пропускаємо), скасована, або створена менш ніж за 5 хв до початку |

## Типові проблеми при налаштуванні

| Симптом | Причина й що робити |
|---|---|
| `You need a workers.dev subdomain` (код 10063) під час `npm run deploy`: код завантажився, а розклад ні | У акаунті Cloudflare ще немає поддомену `workers.dev`. Відкрийте [dash.cloudflare.com](https://dash.cloudflare.com/) → **Workers & Pages**: перше відкриття створює поддомен автоматично. Потім повторіть `npm run deploy`. Публічної адреси в бота не буде, бо в `wrangler.toml` стоїть `workers_dev = false`. |
| `GOOGLE_SERVICE_ACCOUNT_KEY is not valid JSON` у логах Worker'а | Ключ у Cloudflare збережено пошкодженим (зайві лапки, неповна вставка). Перезапишіть його з файлу в Terminal: `npx wrangler secret put GOOGLE_SERVICE_ACCOUNT_KEY < /шлях/до/ключа.json`. |
| `Missing configuration: …` після додавання змінної в дашборді | Змінну створено як **Text**, а не **Secret**. `wrangler deploy` синхронізує звичайні змінні з `wrangler.toml` і може її прибрати. Створіть її як **Secret**. |
| `Not logged in` або `no credentials were found` | Команду запущено в неінтерактивній оболонці (наприклад, `!` у чаті Claude). Запускайте `wrangler` у звичайному терміналі. Якщо вхід «зник», перевірте, чи не з'явилась тека `~/.wrangler`: за її наявності wrangler шукає вхід у ній, а не в `~/Library/Preferences/.wrangler`. Перейменуйте її й за потреби повторіть `npx wrangler login`. |
| `Required Worker name missing` | Команду запущено не з папки проєкту. Перейдіть у папку з `wrangler.toml` або додайте `--name calendar-telegram-bot`. |
| Помилок немає, а нагадування не приходить | Подія вже почалась або створена менш ніж за 5 хв до початку? Про кожну подію бот нагадує **один раз**: якщо нагадування вже було (наприклад, під час тесту з іншим `REMINDER_MINUTES`), нове не прийде. Змініть час події або створіть нову в календарі, ID якого в `GOOGLE_CALENDAR_ID`. |
| `Telegram sendMessage failed: 400 … chat not found` або `403` для каналу | Бот не доданий у канал або не є адміністратором із правом публікації. Додайте його як адміністратора. |

## Ліміти безкоштовного плану Cloudflare

Із запасом вистачає: 1 440 запусків на добу (ліміт 100 000 запитів), KV пишеться лише коли надсилається нагадування (ліміт 1 000 записів на добу). Єдина вразлива точка — 10 мс процесорного часу на запуск. Тому токен Google кешується в KV на ~годину, щоб підписувати JWT лише раз на годину.

KV має відкладену узгодженість, тож у дуже рідкісних випадках можливий повторний показ нагадування.
